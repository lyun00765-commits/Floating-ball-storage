### 注入接口（共 8 个，装配层负责接通）

`setCapturedBallClickHandler`(takeover) · `setCaptureModeChangeHandler`(settings) ·
`setOwnershipDeps` · `setViewportGuardDeps` · `setViewDeps` · `setScanDeps`(scanner) ·
`setBallContainer`(pagination) · `setReleased`(released)

**注意**：注入接口都有安全默认值（空 ref / 空函数），忘了注入时 lint 与 build 都不报错，
但运行时功能**静默失效**。改动装配层后逐项回查这 8 个注入点。
回查内容不只是「有没有注入」，还要核对**注入的值在注入时刻是否已存在**——
二审发现 `setOwnershipDeps` 在装配链之前调用，把 `null` 快照注入了进去
（见下「已修复（二审后）」R1）。注入依赖值时用 getter 也无效：
`setXDeps` 内部的 `{ ...deps, ...next }` 展开会把 getter 求值成快照。

## 三、验证体系（改代码前先看这节）

四道检查，**都要跑**：

```bash
npm run check    # 语法 + 依赖图（esbuild，能校验具名导出；lint 不能）
npm run lint     # eslint src scripts
npm run verify   # 等价性：15 份规格，逐行比对基线
npm run test     # 单元测试（node --test）
npm run build    # 打包成单文件 script.json
```

### 等价性校验怎么用

`scripts/parity/*.json` 为每个模块保存「基线 git ref + 重命名映射 + 函数名映射 + 有意改写清单」。
校验时把基线函数体施加同样改写，再与当前代码逐行比对。

- **注释行不参与比对**（注释不影响行为，补注释/改注释不该让校验失败）
- **多行空 `catch` 与单行 `catch {}` 视为等价**（差别只来自有没有在 catch 里写注释）
- **确需改代码时**，在该模块规格里登记一条 `rewrites`，写明理由；结果会打印
  「施加了 N 处已登记的有意改写」。**它是被审阅过的、可复现的**，不能用一句"已知差异"糊过去。

校验失败时的含义：要么夹带了未登记的行为变更（去查），要么规格需要更新（登记 rewrite）。
**不要为了让校验通过而删改规格。**

### 规格覆盖缺口

`panel/view.js` 与 `store.js` **没有等价性规格**。当初抽取时改写较多、逐行比对不适用而跳过。
两者体量都不小（view 是编译产物组件、store 374 行）。若要动这两个文件的行为，
只能靠人工核对 + 测试清单，谨慎一些。

### 已知限制（**不是**缺陷，别去"修"）

- **点击已收纳的球只对 `ai-floating-panel-*` 这类球生效**：`takeover.js` 只给这些 id/class
  绑了 click 监听。同函数内的 `default` 分支（模拟点击、取出后收回）依赖的前提从未成立，
  已作为死代码删除。其余类型点击无反应是原实现既有状况。
- **装饰兄弟（环形外框）的防护基于矩形重叠度**（重叠 > 0.5 视为同一坨，
  见 `core/overlap.js`）：同轮去重 + 已捕获球原位排除 + 释放连带记忆三层。
  拦不住的情形：装饰与球只是**相邻而不重叠**（此时它本来就像个独立的球）；
  两个真球故意叠放在一起会被并掉一个（病态摆放，不处理）。
  另注意：**此前已被误捕的外框已存进脚本变量**，升级后刷新会被恢复一次，
  在面板里手动释放它即可（进释放记忆，此后不再找回、不再被自动捕）。
- **含旋转的 `transform` 元素收纳后可能变形**：只处理了纯缩放/平移的情形。
- **`klona` 走 CDN**（`testingcf.jsdelivr.net`），不可达时脚本无法启动。

## 五、关键设计决策（改代码前必读）

- **释放记忆只在自动模式下生效**（有意设计，勿当 bug 修）：自动扫描是后台行为，
  必须尊重用户「已表示不要」的记忆；手动模式下的长按一键捕获是用户主动发起的明确操作，
  语义是「能收的都收进来」，此时跳过释放过的球反而让用户困惑。
  `capture/candidate.js` 有同样注释。
- **`clickCapturedBall` 只处理 `root-open` 类型**：见上「已知限制」。
- **手动与自动的识别阈值刻意不同**：手动点选是用户明确指认，故宽松；
  自动扫描误捕代价高，故严格。共用的是「命名排除正则」这类原料，**不是**整套判定。
  这条差异是有意的，不要"统一"。
- **状态跟着函数走**：迁「状态 + 操作它的函数」整簇，不抽公共 state。
- **对外只暴露能力**：如分页模块导出 `appendBall`，不暴露 `pageLayer`。
- **依赖倒置处理循环依赖**：模块永不反向 import 装配层。
  - scanner ↔ store：store 单向 import scanner；scanner 用 `setScanDeps({ store })` 注入
  - guards → store：`setViewportGuardDeps({ togglePanel, getPanelPositionTarget })`
  - view → store：`setViewDeps({ store, triggerScan })`
- **`index.js` 的对外导出是契约**：`export { tryCaptureBall as captureElement, store as pluginStore, ... }`
  被外部脚本调用，改名必须同步，否则使用方拿不到接口。
- **平台契约**（宿主 iframe 注入，不参与打包，eslint 白名单）：
  `Vue` `$` `toastr` `z` `getScriptId` `getVariables` `replaceVariables`
- **产物不提交**：`build/` 在 gitignore；确认稳定后人工拷入 `dist/`。

## 六、维护期注意事项

重构期的过程性踩坑记录已随 `docs/archive/02-重构日志-v1.1.md` 归档。
以下是对**后续维护仍然成立**的几条：

1. **不要用正则改短名**（混淆残留 `e/t/n/a/o`）：必须用 `scripts/rename-symbols.mjs`
   （作用域感知）；子串替换会误伤 `glt` 里的 `lt` 这类包含关系。
2. **全局跑 prettier 会破坏等价性校验**：规格是逐行比对，换行重排会让它失败。
   格式化只能按需、单文件地做，且要确认该文件没有被规格覆盖的**代码**行被改动。
3. **临时脚本放在项目目录内**（否则找不到 `node_modules` 里的依赖），
   且因 `"type": "module"` 需用 `.cjs` 后缀。
4. **注入未接通会静默失效**：lint 与 build 都不报错，运行时才发现功能没了。
   见第二节的 8 个注入点与注入时序教训。
