## 一、项目

SillyTavern「酒馆助手」脚本：自动收纳页面上的悬浮球，统一管理、四向贴边。

起点是一份 **webpack 打包产物**（`index.js` 4132 行，局部变量被混淆为 `e/t/n/a/o`），
目标是拆回可维护的多文件源码，并逐步修复其中的缺陷。产物形态必须保持单文件
（酒馆脚本的 `content` 字段），因此用 esbuild 反向打包。

## 三、工作方法（每批照做）

1. **改语义名**：`node scripts/rename-symbols.mjs <file> OLD=NEW ...`
   —— 作用域感知，禁止文本替换（模块级 `j` 与循环变量 `j` 会互相误伤）
2. **抽取**：写一次性脚本（放 `/workspace/3_sandbox/`），用 marker 定位边界后切片。
   禁止手工重写代码——必须原样搬移，改写只允许在明确受控处进行。
3. **补 import / 改引用点**：搬移后必然有悬空引用，靠 `npm run lint` 暴露
4. **验证**：`npm run check`（语法+依赖图）→ `npm run lint` → `npm run verify` → `npm run build`
5. **建 parity 规格**：`scripts/parity/<name>.json`，见下
6. **独立提交**：`refactor: ...` / `docs: ...`

### 验证的三个层次

- **逐字节比对**（首选）：`scripts/parity/*.json` + `npm run verify`。
  做法：取基线版本的 `index.js`，用 `scripts/lib/rename.js` 施加与重构时**相同**的重命名映射，
  再与拆分后的模块逐字节比对函数体。重命名过也能证明代码未改。
  `rename` 字段只需覆盖**该批次新做**的重命名（基线里已提交的改名不用再写）。
- **归一化 diff**（对象方法 / 有意改写处）：`/workspace/3_sandbox/verify-obj.mjs` 模式——
  提取对象字面量，对基线施加预期改写后逐行比，要求剩余差异为 0 或逐处确认。
- **人工确认**：`initPersistence` / `bindInteractionGuards` 这类无法机械比对的，单独核对并记录差异行。

## 六、关键设计决策

- **状态跟着函数走**：不把变量零散抽进公共 state，而是"状态 + 操作它的函数"整簇搬迁。
  模块边界表达"能做什么"，不表达"里面有什么"。
- **对外只暴露能力**：例如分页模块导出 `getBallsInOrder()` / `containsBall()`，
  而不是把 `pageLayer` 暴露出去；释放记忆导出 `clearReleased()` / `setReleased()` 而非 ref。
- **依赖倒置处理循环依赖**：接管层要回调 store → 导出 `setCapturedBallClickHandler(fn)`；
  设置层要联动扫描启停 → 导出 `setCaptureModeChangeHandler(fn)`。**模块永不反向 import 装配层。**
- **平台契约**（宿主 iframe 注入，不参与打包，eslint 白名单）：
  `Vue` `$` `toastr` `z` `_` `getScriptId` `getVariables` `replaceVariables`
- **产物不提交**：`npm run build` 输出到 `build/`（gitignore）；确认稳定后才人工拷入 `dist/`。

## 七、踩过的坑

1. **边界抽多**：按 `const Ne = {` 切边界，误删了它之前的 store 状态与函数 → 94 个 lint error。
   教训：抽取前先列出目标区间的顶层声明清单。
2. **用 AST 切边界，不要用字符串 marker**：`/workspace/3_sandbox/extract-geometry.mjs` 的写法——
   从 espree 取函数的 `range` 精确切分，尤其当要「抽一整段但剔除中间某几个函数」时，
   字符串切片会把相邻函数切坏（曾失败过一次）。
3. **同一条 const 链**：`const settingsApi = {...}, de = ..., ue = ...` 是**一个**声明语句。
   拆链：`},\n  de = ` → `}\nconst de = `。
4. **对象方法的缩进**是 4 格（不是 2 格），抽取后要整体减 2。
5. **短名重命名必须作用域感知**：`j` 全文件 8 处，只有 4 处指向目标函数。
6. **基线里已包含上一批的重命名**，spec 的 `rename` 只写本批新做的改名。
7. **eslint 的 `no-undef` 是搬移期最重要的防线**——悬空引用只能靠它抓。
   ≥ **但它不校验具名导入是否存在**：`import { x } from './m.js'` 里 `m.js` 没导出 `x`，eslint 不报。
   这条由 `npm run check`（esbuild）兜住。两者缺一不可。
8. **`export const a = 1, b = 2` 里的 `b` 是导出的**（曾误判为不导出）。
9. **注入必须接通，否则功能静默失效**：抽 view 时给 `deps` 设了安全默认值
   （空 ref / 空函数），所以忘了调 `setViewDeps` 时 **lint 与 build 都不报错**，
   但运行时组件拿到的是空 store。**每抽一个带注入的模块，立刻在装配层补上注入调用并回查。**
   已抽的注入接口共 7 个：`setCapturedBallClickHandler` / `setCaptureModeChangeHandler` /
   `setOwnershipDeps` / `setViewportGuardDeps` / `setViewDeps` / `setBallContainer` / `setReleased`。
10. **JS 的 `String.replace(字符串, x)` 只替换第一处**（Python 的 `str.replace` 是全部）。
   写核对脚本时踩过这个坑，导致"替换后仍不一致"的假差异。批量替换用 `replaceAll` 或带 `g` 的正则。
11. **抽取区间要检查是否夹带了别的东西**：本批两次踩到——按 `function Ct(` 取上界，
   把恰好定义在它前面的 `syncAutoScan` 一起抽进了新模块（lint 立刻报 `Ne`/`lt` 未定义）。
   **定界前先 grep 区间内的顶层声明清单**。
12. **搬完后要回查「模块对外提供的名字」是否与调用点一致**：`gt`/`Ct`/`ft`/`bt`/`dt`/`ut`
   被改名后，**文件末尾的 `export { gt as captureElement, ... }` 立刻失效**——这是脚本的对外 API 契约，
   错了会让使用方拿不到接口。搬移前先确认模块是否被 `export`，搬完同步改名。
13. **`str.replace('lt =', ...)` 这类子串替换会误伤 `glt =`**（`g` + `lt =`）。
   短名批量替换必须带标识符边界（正则 `(?<![\w$.])`），否则会造出 `gscanTimer` 这种怪名字。
14. **新模块的 import 路径要在 `npm run build` 里验**：`npm run check` 没抓到
   `./pagination.js` 应为 `../panel/pagination.js`，build 才报。搬完务必跑一次 build。
15. **`;((A = !0), X, Y))` 这类链很脆**：把首项 `A = !0` 换成 `fn()` 时，
   `fn()` 会"吃掉"原来闭合内层括号的那个 `)`，导致少一个括号。
   改法：连同外层一起去掉，写成 `;(fn(), X, Y)`。同理，删除链中间的项后，
   **原来在链尾的 `))` 就变成悬空**，必须把它移到新的链尾。
   这类错误 lint 会以 "Parsing error: Unexpected token" 报出，但行号指向的是后续语句，
   不是真正的问题位置。
16. **先算依赖闭包再搬**：`/workspace/3_sandbox/deps.mjs <函数名>...` 输出跨块引用的顶层声明，
   避免「边界抽多」和「抽漏依赖」。
